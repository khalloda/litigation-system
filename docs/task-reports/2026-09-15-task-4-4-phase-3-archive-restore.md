## Result and design

Administrator can independently archive or restore a work and an individual
step. Archive removes that subject from the default operational list; it changes
neither completion/status nor dates/business/source data. All four roles can read
archived records. The three D62 writers retain eligible create/update; an archived
subject, work or required matter must first be restored. An archived client is
independent. Work transitions never cascade to steps.

Work and step filters independently offer current, archived and all. Their counts
and complete paginated ID sets are checked independently of the production query.
Detail/edit/confirmation/back links retain validated context. Archiving the last
visible page clamps to the remaining page and explains the change. Historical
relationship and report totals keep archived records. Imported ordering and native
positions remain stable; new steps append beyond the archived maximum.

Four Arabic confirmation pages identify the work/step, multiline case context,
business date/content, and total/current/archived step counts. Cancel receives
focus, Escape restores focus, and stale confirmation requires a deliberate fresh
load. Success loads fresh detail; an old receipt never claims its old flag is the
current state. Current assignee and retained source evidence stay separately
labelled. Strings remain centralized, with the established RTL styles.

Migration `20260915120000_admin_work_archive_restore` alone introduces 69. Both
flags start false independently of historical values. A private immutable boundary
pins per-work pre-69 versions and the exact old history/receipt counts and digests.
Only that historical partition receives missing-flag normalization. New history
retains both flags and validates current state, parent, version, actor, receipt,
subject and semantic audit. Original migration 68 and every earlier migration are
byte-frozen; D1–D62, governance and all 86 checkbox lines remain exact.

The committing gateway rechecks current source account/session/Administrator and
trusted audit actor. It shares D62's mutex, token namespace and receipt ownership.
Fresh transitions lock the matter/work/step, check the version and displayed facts,
and write one aggregate version/history/receipt and the correct subject audit.
True no-ops and exact owned retries change no table or sequence. Ordinary editors
cannot smuggle flags or modify archived records. Runtime receives only the two
narrow public gateways; private helpers and table writes remain denied.
